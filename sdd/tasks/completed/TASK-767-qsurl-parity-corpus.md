## Implementation Notes

### Key Constraints
- Error parity rule (spec §3 M3 rule 10): `kind` and `offset` must match for every error case; `message` must match exactly for custom (`unknown pipeline operator…`, `… given more than once`) and all `lower` errors; for generic syntax errors compare `message.split("; expected")[0]`. Record per case which comparison applies with `"message_match": "exact" | "prefix"`.
- Store each valid case's expected IR as the compact JSON **string** (`"ir_json"`), so the test compares bytes, not dicts.
- The `eight_kb_url` case: generate it deterministically (e.g. `"s?" + "&".join(f"c{i}={i}" for i in range(N))` sized to ~8 KB) and store the literal input in the corpus.
