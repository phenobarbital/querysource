# Feature Specification: New Destination Folder for MultiQuery

**Feature ID**: FEAT-097
**Date**: 2026-05-22
**Author**: Jesus Lara
**Status**: approved
**Target version**: 6.0.0

---

## 1. Motivation & Business Requirements

### Problem Statement

MultiQuery destination components currently live in two layers with no clear ownership:

1. `querysource/outputs/destinations/` — created by FEAT-094 and shared with Flowtask through the underlying `TableOutput` wrapper. It hosts `AbstractDestination`, `TableOutputAdapter`, and the FEAT-094 destinations (`ToSharepoint`, `ToS3`, `TableDestination`, `DWHDestination`). Because the folder is shared with Flowtask, it can't grow freely with MultiQS-specific destinations.
2. `querysource/queries/multi/` — the canonical MultiQuery package. It has `sources/`, `operators/`, `transformations/`, but no `destinations/` subpackage. That makes new MultiQS-only destinations awkward to land — they either go into the shared layer (polluting Flowtask) or end up scattered across the queries/multi tree.

Furthermore, `AbstractDestination` (the base class) lacks the introspection infrastructure that `AbstractMulti` has: `get_schema()`, `get_attributes()`, `get_description()`. `ComponentRegistry` therefore falls back to a name-heuristic (`registry.py:239`) to classify destinations, and the JSON Schema returned for any destination is an empty `{ properties: {}, required: [] }` (`registry.py:201-215`). The documentation API (FEAT-095) can list destinations by name, but cannot describe their attributes — which defeats the purpose of the schema endpoint for destinations.

### Goals

- Extract the schema-introspection classmethods (`get_attributes`, `get_schema`, `get_description`) out of `AbstractMulti` into a reusable mixin (`SchemaIntrospectable`) and make both `AbstractMulti` and `AbstractDestination` inherit from it. `AbstractDestination` gains `_category = "Destinations"` by default.
- Create the `querysource/queries/multi/destinations/` subpackage. It re-exports `AbstractDestination` (shim) so MultiQS-only destinations can import it via the MultiQS-local path: `from querysource.queries.multi.destinations import AbstractDestination`.
- Migrate the FEAT-094 MultiQS-only destinations (`ToSharepoint`, `ToS3`, `TableDestination`, `DWHDestination`) from `querysource/outputs/destinations/` into `querysource/queries/multi/destinations/`. `AbstractDestination` itself, `TableOutputAdapter` (the Flowtask-shared TableOutput wrapper), and `DESTINATION_REGISTRY` stay in `querysource/outputs/destinations/` because Flowtask depends on them and on the registry entry point.
- Extend `ComponentRegistry.discover_all()` so it discovers destinations via BOTH (a) a filesystem scan of `querysource/queries/multi/destinations/*.py` (any class inheriting `AbstractDestination` is auto-registered) AND (b) the existing `DESTINATION_REGISTRY` dict in `outputs/destinations/`. The results are merged — the new folder takes precedence on name collisions.
- After the migration, the documentation endpoint (FEAT-095) returns a fully-populated JSON Schema for every destination, generated by the shared introspection mixin.
- Maintain backward compatibility: existing YAML/JSON pipelines using `tableOutput`, `TableOutput`, `ToSharepoint`, `ToS3`, `Table`, `DWH` step-names continue to work unchanged.

### Non-Goals (explicitly out of scope)

- Adding any new concrete destination class. This spec is purely structural — it creates the home for future destinations and back-fills introspection on existing ones.
- Moving `TableOutput` (the Flowtask-shared class at `querysource/outputs/tables/TableOutput/table.py`) or the `TableOutputAdapter` wrapper. They stay in `outputs/`.
- Changing `AbstractMulti`'s public API surface — only the introspection methods move into a mixin that `AbstractMulti` still inherits from, so subclasses see no behavior change.
- Modifying the pipeline-runner logic in `MultiQS.query()` (`__init__.py:405-419`). Dispatch continues via `get_destination(step_name)` which reads `DESTINATION_REGISTRY`.
- Adding write-path features (new flags, batching, transactions, etc.) to any migrated destination.

## 2. Architectural Design

### Overview

The work is structural, in three layers:

1. **Mixin extraction**: Move `get_attributes()`, `get_schema()`, `get_description()` (plus their private helpers `_type_to_json_schema`, `_hint_to_str`, `_parse_default`) from `AbstractMulti` into a new mixin module `querysource/queries/multi/_introspect.py` exposing `SchemaIntrospectable`. `AbstractMulti` keeps the same public API by inheriting `(SchemaIntrospectable, ABC)`. `AbstractDestination` becomes `(SchemaIntrospectable, ABC)` and gets `_category = "Destinations"`.
2. **New folder**: Create `querysource/queries/multi/destinations/`. Its `__init__.py` re-exports `AbstractDestination` (the shim) and exposes a local `DESTINATION_REGISTRY` populated by a filesystem scan over its own `*.py` files. The four FEAT-094 destinations are moved here and updated to import `AbstractDestination` via the new shim path. The old import paths in `querysource.outputs.destinations.*` are kept alive as re-exports for backward compatibility (tests + Flowtask).
3. **Registry merge**: `ComponentRegistry.discover_all()` adds a filesystem scan over `querysource/queries/multi/destinations/*.py` (excluding `_*.py`, `abstract.py`). It then merges with the existing `DESTINATION_REGISTRY` from `outputs/destinations/`. Items found in `queries/multi/destinations/` win on key collision. The `_classify()` heuristic at `registry.py:222-241` is replaced with a real `issubclass(comp_cls, AbstractDestination)` check — no more name-list special case.

### Data Models

This feature does not introduce new Pydantic models. The relevant in-process structures (`SchemaIntrospectable.get_schema() -> dict`, etc.) are dict-based and already defined in `AbstractMulti`. The mixin preserves the exact return shape:

```python
# SchemaIntrospectable.get_schema() return shape — unchanged from AbstractMulti

    "json_schema": {
        "$schema": "https://json-schema.org/draft/2020-12/schema",
        "type": "object",
        "title": <ClassName>,
        "properties": {<attr>: {"type": <json_schema_type>}, ...},
        "required": [<attr>, ...],
    },
    "attributes": [
        {"name": str, "type": str, "default": Any, "required": bool},
        ...
    ],
}
```

## 3. Module Breakdown

### Module 1: `querysource/queries/multi/_introspect.py` (NEW)
- **Path**: `querysource/queries/multi/_introspect.py`
- **Responsibility**: Defines `SchemaIntrospectable` mixin and its private helpers (`_type_to_json_schema`, `_hint_to_str`, `_parse_default`). This is a pure-Python class with no MultiQuery-specific dependencies. Imports `pandas` only if necessary (not necessary — helpers operate on type names).
- **Depends on**: stdlib only (`inspect`, `re`, `typing`, `json`).

### Module 2: `querysource/queries/multi/abstract.py` (MODIFIED)
- **Path**: `querysource/queries/multi/abstract.py`
- **Responsibility**: `AbstractMulti(SchemaIntrospectable, ABC)`. Keeps the lifecycle code (`__aenter__`, `__aexit__`, `start`, `run`, `close`, `_print_info`) and the data-handling `__init__`. Removes the duplicated introspection classmethods + private helpers (now in `_introspect.py`).
- **Depends on**: Module 1.

### Module 3: `querysource/outputs/destinations/abstract.py` (MODIFIED)
- **Path**: `querysource/outputs/destinations/abstract.py`
- **Responsibility**: `AbstractDestination(SchemaIntrospectable, ABC)` — gains the introspection methods. Sets `_category: str = "Destinations"`. Keeps the existing `__init__`, `resolve_credentials`, abstract `run`, `close`.
- **Depends on**: Module 1.

### Module 4: `querysource/queries/multi/destinations/__init__.py` (NEW)
- **Path**: `querysource/queries/multi/destinations/__init__.py`
- **Responsibility**: Re-export `AbstractDestination` from `outputs.destinations.abstract` (shim). Build a local `DESTINATION_REGISTRY` by scanning `*.py` files in this folder and registering any class that (a) inherits `AbstractDestination` and (b) is exported in `__all__` (or matches the file basename in PascalCase). Optional imports (e.g. `aioboto3`) are wrapped in `try/except ImportError` exactly like the current `outputs/destinations/__init__.py` does.
- **Depends on**: Module 3; Modules 5-8.

### Module 5: `querysource/queries/multi/destinations/sharepoint.py` (MOVED)
- **Path**: `querysource/queries/multi/destinations/sharepoint.py`
- **Responsibility**: `ToSharepoint(AbstractDestination)` — identical to the current `outputs/destinations/sharepoint.py` except the relative import becomes `from . import AbstractDestination` (resolves to the shim).
- **Depends on**: Module 3.

### Module 6: `querysource/queries/multi/destinations/s3.py` (MOVED)
- **Path**: `querysource/queries/multi/destinations/s3.py`
- **Responsibility**: `ToS3(AbstractDestination)` — same as current `outputs/destinations/s3.py` with import updated.
- **Depends on**: Module 3.

### Module 7: `querysource/queries/multi/destinations/table.py` (MOVED)
- **Path**: `querysource/queries/multi/destinations/table.py`
- **Responsibility**: `TableDestination(AbstractDestination)` plus `DRIVER_MAP`, `VALID_METHODS`, `_EXTERNAL_DRIVERS`. Same code as current `outputs/destinations/table.py` with import updated. Note: keep the `from querysource.outputs.tables.TableOutput.*` engine imports unchanged.
- **Depends on**: Module 3; `querysource/outputs/tables/TableOutput/*` engines (unchanged).

### Module 8: `querysource/queries/multi/destinations/dwh.py` (MOVED)
- **Path**: `querysource/queries/multi/destinations/dwh.py`
- **Responsibility**: `DWHDestination(AbstractDestination)` plus `_clean_dynamo_record`. Same code as current `outputs/destinations/dwh.py` with import updated.
- **Depends on**: Module 3.

### Module 9: `querysource/outputs/destinations/{sharepoint,s3,table,dwh}.py` (SHIMS)
- **Path**: four files at `querysource/outputs/destinations/`
- **Responsibility**: Become one-line shims that re-export from the migrated location, preserving every existing import path used by tests and Flowtask. Example for `sharepoint.py`:
  ```python
  from querysource.queries.multi.destinations.sharepoint import *  # noqa: F401, F403
  from querysource.queries.multi.destinations.sharepoint import ToSharepoint  # explicit
  ```
  For `table.py` and `dwh.py` also re-export the helper symbols used by tests (`DRIVER_MAP`, `_clean_dynamo_record`).
- **Depends on**: Modules 5-8.

### Module 10: `querysource/outputs/destinations/__init__.py` (MODIFIED)
- **Path**: `querysource/outputs/destinations/__init__.py`
- **Responsibility**: Keeps `TableOutputAdapter` here (Flowtask-shared, wraps `outputs.tables.TableOutput`). Imports the migrated classes from `queries/multi/destinations/` (or, equivalently, via the shim modules) so `DESTINATION_REGISTRY` continues to expose `tableOutput`, `TableOutput`, `ToSharepoint`, `ToS3`, `Table`, `DWH`. `get_destination()` and `__all__` are unchanged.
- **Depends on**: Module 4; Module 5-8.

### Module 11: `querysource/queries/multi/registry.py` (MODIFIED)
- **Path**: `querysource/queries/multi/registry.py`
- **Responsibility**: In `discover_all()`, replace step (4) with a filesystem scan over `queries/multi/destinations/*.py` plus a merge with `DESTINATION_REGISTRY` (new folder wins on collision). In `_classify()`, drop the name-list special case (`"tableOutput", "TableOutput", "ToSharepoint", "ToS3", "Table", "DWH"`) and rely on `issubclass(comp_cls, AbstractDestination)` plus the `_category` attribute (now `"Destinations"` for all subclasses).
- **Depends on**: Modules 3, 4.

## 5. Acceptance Criteria

> This feature is complete when ALL of the following are true:

- [ ] `querysource/queries/multi/_introspect.py` exists and exposes `SchemaIntrospectable` with `get_attributes()`, `get_schema()`, `get_description()` and the three private helpers.
- [ ] `AbstractMulti` inherits from `SchemaIntrospectable` and still passes every existing operator/transformation/source test that exercises `get_schema()` / `get_attributes()` / `get_description()` (no public-API regression).
- [ ] `AbstractDestination` inherits from `SchemaIntrospectable`, defines `_category = "Destinations"`, and `AbstractDestination.get_schema()` returns the documented `{json_schema, attributes}` shape for a concrete subclass.
- [ ] `querysource/queries/multi/destinations/` exists as a real package with an `__init__.py` that re-exports `AbstractDestination` and a local `DESTINATION_REGISTRY` built via filesystem scan.
- [ ] `ToSharepoint`, `ToS3`, `TableDestination`, `DWHDestination` live in `querysource/queries/multi/destinations/{sharepoint,s3,table,dwh}.py`. Their class bodies are byte-identical to the previous files apart from the `AbstractDestination` import.
- [ ] `querysource/outputs/destinations/{sharepoint,s3,table,dwh}.py` are one-screen shims that re-export from the migrated modules; the classes accessed via the old paths are the **same object** (`is`-identical) as those accessed via the new paths.
- [ ] `querysource/outputs/destinations/__init__.py` keeps `TableOutputAdapter`, `DESTINATION_REGISTRY` (with all six keys: `tableOutput`, `TableOutput`, `ToSharepoint`, `ToS3`, `Table`, `DWH`), and `get_destination()` working. Flowtask-shared `TableOutputAdapter` does NOT move.
- [ ] `ComponentRegistry.discover_all()` discovers destinations via filesystem scan of `queries/multi/destinations/` PLUS the existing `DESTINATION_REGISTRY` merge, with the new-folder scan winning on key collision.
- [ ] `ComponentRegistry._classify()` no longer relies on the hardcoded name list at `registry.py:239` — every entry in `DESTINATION_REGISTRY` is classified via `issubclass(..., AbstractDestination)` or the `_category` attribute.
- [ ] The documentation endpoint (FEAT-095) returns a JSON Schema with non-empty `properties` for every destination class. `tableOutput` and `TableOutput` may keep an empty `properties` dict because `TableOutputAdapter` wraps a non-introspectable `TableOutput`; this is acceptable as long as no other destination has empty `properties`.
- [ ] All existing tests under `tests/test_destination_*.py` pass without modification.
- [ ] `ruff check .` and `mypy querysource/` pass (no new errors introduced by the refactor).

## 7. Implementation Notes & Constraints

### Patterns to Follow

- **Mixin layout**: Define `SchemaIntrospectable` as a plain class (not `ABC`); it can be mixed in alongside `ABC`. Subclass MRO becomes `Subclass -> AbstractMulti -> SchemaIntrospectable -> ABC -> object` (or `AbstractDestination -> SchemaIntrospectable -> ABC -> object`).
- **Filesystem scan**: Mirror the operator/transformation scan loop at `registry.py:97-107`. Skip `__*.py`, `_*.py`, and `abstract.py`. Import via `importlib.import_module(f".destinations.{stem}", package="querysource.queries.multi")` and pick up classes via `inspect.getmembers(module, lambda c: inspect.isclass(c) and issubclass(c, AbstractDestination) and c is not AbstractDestination)`.
- **Shim style**: Each shim file in `outputs/destinations/` is one logical line. Example:
  ```python
  """Backward-compat shim. Real class lives in querysource.queries.multi.destinations.sharepoint."""
  from querysource.queries.multi.destinations.sharepoint import ToSharepoint  # noqa: F401
  ```
  For `table.py` also include `DRIVER_MAP`, `VALID_METHODS`, `_EXTERNAL_DRIVERS`. For `dwh.py` also include `_clean_dynamo_record`. These are imported by tests today.
- **Order of work**: Mixin (Module 1) → AbstractMulti refactor (Module 2) → AbstractDestination refactor (Module 3) → new subpackage skeleton (Module 4) → migrate one destination at a time (Modules 5-8), keeping shims (Module 9) in lock-step → final `__init__.py` rewire (Module 10) → registry rewire (Module 11). Each step keeps the test suite green.
- **No behavior changes** to any destination's `run()` / `close()` / `resolve_credentials()` code paths. This is a structural refactor only.

### Known Risks / Gotchas

- **Circular imports**: `outputs/destinations/__init__.py` imports the migrated classes from `queries/multi/destinations/` to populate `DESTINATION_REGISTRY`. `queries/multi/destinations/__init__.py` imports `AbstractDestination` from `outputs/destinations/abstract`. As long as `abstract.py` does not import anything from the package-level `__init__.py`, the cycle is broken. Verified: current `outputs/destinations/abstract.py` only imports stdlib + `navconfig` + `pandas`. Keep it that way.
- **`functools.lru_cache(maxsize=1)` on `discover_all`**: Currently caches at the registry. Tests that monkeypatch the destinations folder must clear the cache between cases. The existing tests already handle this via `ComponentRegistry.discover_all.cache_clear()` — preserve that pattern.
- **Optional-dependency guard**: The current `outputs/destinations/__init__.py` wraps every concrete import in `try/except ImportError` so missing `msgraph-sdk`, `aioboto3`, or BigQuery client doesn't break the registry. The new `queries/multi/destinations/__init__.py` MUST do the same — otherwise environments that omit one of those deps will see `ComponentRegistry.discover_all()` crash.
- **PascalCase vs camelCase keys**: Existing pipelines use both `tableOutput` and `TableOutput` (FEAT-094 kept both for backward compat). The shim must not change the registry key surface. Test `test_destination_registry_preserves_step_names` is the canary.
- **`AbstractDestination.__init__` sets `self.logger`**: `AbstractMulti.__init__` does NOT. After the mixin extraction, both should still work — the introspection methods do not touch `self.logger`. Don't accidentally consolidate `__init__` between the two.
- **`mypy --strict`**: `SchemaIntrospectable` is a plain class; subclasses may pass `**kwargs` not declared on it. Use `# type: ignore[misc]` only if strictly needed; prefer keeping the mixin attribute-free apart from `_category: str = "Components"`.
